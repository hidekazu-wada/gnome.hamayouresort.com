# /area/ 周辺情報マップ 実装指示書

このドキュメントは Claude Code にそのまま渡すための指示書です。
対象: `gnome-hamayouresort-com`（SAIKO CAMP VILLAGE GNOME / 湖のほとりのキャンプ場）の `/area/` ページ。

---

## 0. 前提と現状

`/area/` には現在こういう iframe が入っています。

```
https://maps.google.com/maps?q=山梨県南都留郡富士河口湖町西湖1030&z=13&output=embed
```

これは **住所を1点表示するだけの埋め込みで、カスタムピンを1個も置けません**。
ページには「MAP内のマーカーをクリックすると詳細情報が表示されます」という説明文と、
病院／コンビニ／スーパー／飲食店／ランドリー／キャンプ用品店／観光 のカテゴリアイコンが既に並んでいますが、
**説明文と実装が食い違っている状態**です。この iframe を丸ごと置き換えます。

添付の `area-pois.json` に、周辺スポット70件のデータが入っています。これを使ってください。

## 1. まずやること: ジオコーディング

`area-pois.json` の全レコードで `lat` / `lng` が `null` です。**実装より先にここを埋めてください。**

### 手順

1. **起点の座標を最優先で正確に取る。**
   `meta.origin`（〒401-0332 山梨県南都留郡富士河口湖町西湖1030）。
   ここは地図の初期中心であり、全 POI の移動時間の起点であり、ルート案内リンクの出発地でもあります。
   自動ジオコーディングに任せず、実際の敷地入口の座標を手で確認して入れてください。

2. **各 POI の `address` を入力にジオコーディングする。** 推奨は次の順。
   - 第一候補: **国土地理院 住所検索 API**（無料・キーなし・CORS 可・日本の住所に強い）
     `https://msearch.gsi.go.jp/address-search/AddressSearch?q={住所}`
     → `[0].geometry.coordinates` が `[lng, lat]` で返る。街区レベル精度。
   - 第二候補: Google Geocoding API（キーが必要だが建物レベルまで出る）
   - 補正: 郵便番号や「〒」「（）内の補足」を除いた文字列でも試す。
     `西湖根場2710` のような大字表記は失敗しやすいので、失敗したら施設名＋市町村名で再検索。

3. **目視で必ず確認する。** 全点を地図に落として、
   - 湖の上・山の中に落ちている点がないか
   - 同じ住所に見えないのに座標が完全一致している点がないか（ジオコーダの丸め失敗）
   - 富士吉田市の2件（病院）が正しく東側に離れているか
   を確認してください。1点でもズレていると「この地図は雑だ」と見なされます。

4. **`drive_minutes` を実測値に差し替える。**
   現在の値は書斎による地理的推定で、`drive_minutes_source: "estimate"` が付いています。
   起点からの実ルーティング（Google Directions API / OSRM いずれでも可）で車移動の分数を取り直し、
   `drive_minutes_source` を `"routing"` に書き換えてください。
   その後 `tier` を `drive_minutes` から再計算します（`<=10` → 1、`11-20` → 2、`21以上` → 3）。

5. これらは**ビルド時に一度だけ走らせて JSON に焼き込む**こと。実行時に毎回 API を叩かないでください。
   ジオコーディング用のスクリプトは `scripts/geocode-pois.ts` などに置いて、結果を JSON に上書きする形にしてください。

## 2. 技術選定

### 地図ライブラリ

**Leaflet + 国土地理院タイル（淡色地図）を第一推奨とします。**

- 理由: API キー不要、無料、商用利用可（出典表示が条件）、日本語ラベル、日本の地形表現が正確。
  富士山周辺の等高線・樹海・湖岸が正しく出るので、このサイトの内容と相性が良い。
- タイル URL: `https://cyberjapandata.gsi.go.jp/xyz/pale/{z}/{x}/{y}.png`
- 出典表示（必須・地図の隅に小さく）: `出典: 国土地理院`
- 地形の雰囲気を出したい場合は淡色地図の上に `hillshademap` を薄く重ねると良い。

**Google Maps JS API を使う場合の注意**: 動的マップは月10,000ロードまで無料、それを超えると従量課金です。
シーズンのアクセス次第で普通に超えるので、使うなら請求上限アラートを必ず設定してください。
MapTiler / Mapbox も同様に無料枠と課金があります。**まず GSI タイルで作って、不足を感じたら移行**という順序を推奨します。

### レンダリング方針 — ここが重要

**POI リストは必ずサーバーサイドで HTML として出力してください。地図は progressive enhancement です。**

- JS が無効でも、クローラが JS を実行しなくても、70件の施設名・カテゴリ・所要時間・説明文が
  テキストとして DOM に存在する状態にする。
- 地図はそのリストの上に乗る「見せ方の一つ」として後から hydrate する。
- 理由: このページは今回のリニューアルで **「西湖 キャンプ場 周辺」「河口湖 キャンプ 買い出し」等の検索流入を取りにいける数少ないページ**です。
  地図の中にしか情報がないと、その資産がゼロになります。WordPress からの移行で検索順位を落としたくないなら、ここは譲らないでください。
- 地図ライブラリは dynamic import で遅延ロードし、初期表示をブロックしないこと。

## 3. UX 設計

デザインの美しさより**「探している情報に何秒で辿り着けるか」**を優先してください。
このページを見る人の状態は、だいたい次の3つのどれかです。

1. **予約前** —「ここに泊まったら、周りに何があるんだろう」（漠然と眺める）
2. **滞在前日** —「明日どこ行こう」「夕飯どうしよう」（計画を立てる）
3. **滞在中** —「氷が切れた」「子どもが熱を出した」（今すぐ必要）

3番の人を絶対に迷わせないでください。ここが一番切実で、一番サイトの評価に効きます。

### レイアウト

**デスクトップ（1024px〜）**
```
┌─────────────────────────┬──────────────────┐
│                         │ [フィルタチップ]  │
│                         │ ────────────────  │
│        地図              │ □ カード          │
│      （sticky）          │ □ カード          │
│                         │ □ カード          │
│                         │ （スクロール）     │
└─────────────────────────┴──────────────────┘
```
地図は `position: sticky` で追従。リスト側だけスクロール。比率は 3:2 程度。

**モバイル（〜767px）**
```
┌──────────────────┐
│  [フィルタチップ]  │ ← 横スクロール、sticky
├──────────────────┤
│      地図         │ ← 高さ 45vh 程度で固定
├──────────────────┤
│  □ カード         │
│  □ カード         │ ← 下に流れる
└──────────────────┘
```
- ボトムシート方式（地図全画面＋引き上げパネル）は避けてください。実装が重い割に、
  片手操作で誤爆しやすく、スクロール位置を見失います。素直な縦積みの方が速いです。
- 地図の高さを `vh` で取る場合は `dvh` を使い、iOS のアドレスバー伸縮で高さが飛ばないようにすること。

### カテゴリフィルタ

カテゴリは10個あります。**フラットに10個並べるとモバイルで3行に折り返して壊れます。**
`area-pois.json` の `groups` を使って2段に分けてください。

```
楽しむ      [温泉・お風呂] [飲食店] [観光・遊び]
困ったとき   [コンビニ] [買い出し] [ガソリン] [キャンプ用品] [ランドリー] [薬局] [病院]
```

- 初期状態: **全カテゴリ ON**（何も選んでいない＝全部見える）。
  「まず絞らせる」UI にしないこと。1の「漠然と眺める」人が離脱します。
- チップは複数選択のトグル。選択中は塗り、非選択は枠線のみ。色は `categories[].color` を使う。
- 「すべて解除 / すべて選択」を端に置く。
- 選択状態を URL クエリに反映（`?cat=onsen,restaurant`）。**共有とリロードで状態が保てること。**
  滞在中の人が LINE で家族に送るシーンが実際にあります。

### 距離フィルタ

**これが今回の設計上いちばん効く要素です。**

調査で分かったこと: **西湖から車15分圏には、コンビニもスーパーも薬局も病院も1軒もありません。**
最寄りのコンビニ（セブン-イレブン山梨鳴沢店）で約14分。
本格的な食品スーパーは全て船津・小立エリアで、**片道24〜25分**かかります。

- 初期表示は **tier 1 + tier 2（車で20分以内）**。件数は53件。
- リストの末尾に「**車で20分より遠いところも見る（17件）**」を置いて、押すと tier 3 が追加される。
- ただし **`category: "supermarket"` のうちマックスバリュ／オギノ／セルバの3件は tier 3 だが、
  「買い出し」チップを選んだときは距離フィルタに関係なく必ず表示すること。**
  買い出し先が全部20分超なので、距離で隠すと「スーパーが1軒もない」ように見えてしまいます。
  同じ理由で `emergency: true` の病院3件も距離フィルタの対象外にしてください。
- 距離を隠さないこと。「近くに何でもあります」と見せかけて実際は無い、が一番信用を失います。
  むしろ「西湖はコンビニまで14分。買い出しは来る前に済ませておくと快適です」と
  地図の上に一文添えるくらいが誠実で、結果的に満足度が上がります。

### 地図とリストの連動

- 全マーカーは常に `drive_minutes` 昇順でリストに並ぶ（近い順）。
- **マーカーをクリック** → 対応するカードがリスト内で `scrollIntoView({block:'nearest'})`、
  カードにハイライト（背景色の変化＋左端にカテゴリ色のバー）。ポップアップは出さない。
  → 情報はカードに一本化する。ポップアップとカードで二重に情報を持つと、必ず片方が古くなります。
- **カードにホバー / フォーカス** → 対応するマーカーが拡大＆最前面に。
- **カードをクリック** → 地図がそのマーカーを中心に `flyTo`（ズームは変えない、または現在より寄る方向にだけ）。
- 地図の初期表示は、表示中の POI 全部＋起点が収まる `fitBounds`。カテゴリを絞ったら bounds を再計算。
- マーカーが密集する西湖畔・船津エリアがあるので、`Leaflet.markercluster` でクラスタリングすること。
  ただし **クラスタの閾値は緩めに**（8件以上で集約くらい）。すぐ団子になると探せません。

### 起点マーカー

キャンプ場そのもののマーカーは、他のどれとも違う見た目にして、**カテゴリフィルタで消えないように**してください。
「自分がどこにいるか」が消える地図は使い物になりません。ラベルも常時表示。

### カード

1枚のカードに載せる情報と優先順位:

```
┌────────────────────────────────────┐
│ [温泉]                    車で 5分  │  ← カテゴリバッジ / 所要時間
│ 富士西湖温泉 いずみの湯              │  ← 名前（h3）
│ 車5分の最寄り温泉。系列施設なので     │  ← note（一番読まれる行）
│ 案内もスムーズ                      │
│ 月木金 12:00-19:00 / 火水休          │  ← hours + closed
│ 平日900円                          │  ← price（あれば）
│ [ ルートを見る ] [ 電話 ]            │  ← CTA
└────────────────────────────────────┘
```

- **`note` を一番目立たせる。** 施設名と営業時間はどこにでもある情報で、
  「キャンプ場から見てどうなのか」を書いた `note` だけがこのページにしかない価値です。
- **「ルートを見る」が最重要 CTA。** Google マップのルート案内へ、**起点をキャンプ場に固定して**ディープリンクする。
  ```
  https://www.google.com/maps/dir/?api=1&origin={起点lat},{起点lng}&destination={POIのlat},{POIのlng}&travelmode=driving
  ```
  `destination` は座標を使う（施設名だと同名の別店舗に飛ぶ事故が起きます）。
  `target="_blank" rel="noopener"` を付けること。
- **電話番号は必ず `tel:` リンク**にする。滞在中に一番押されるのがこれです。ハイフンは表示だけ、`href` は数字のみ。
- `url` があれば「公式サイト」リンクを控えめに置く。ただし食べログのリンクは `rel="nofollow"` を付けること。
- `closed`（定休日）は**赤系ではなく落ち着いた色で、しかし省略せずに**出す。
  「行ったら閉まってた」がクレームとして戻ってくる導線を作らないこと。
- `emergency: true` の3件（山梨赤十字病院／富士吉田市立病院／小児初期救急センター）は
  病院カテゴリの中で常に最上位に固定表示。`rainy_day: true` は「雨でも楽しめる」の小バッジを付ける。
  → 雨天対策は運営上の重要テーマなので、このバッジは効きます。

### 検索ボックス

70件なら、カテゴリフィルタ＋距離順で十分たどり着けます。**検索ボックスは付けないでください。**
入力欄が増えるほど「探す作業」が発生します。

### 空状態

フィルタで0件になったら、「条件に合う場所がありません」＋「フィルタをリセット」ボタン。
地図は起点だけ表示した状態に戻す。

### アクセシビリティ

- カードは `<article>`、リストは `<ul>/<li>`。マーカーは `role="button"` ＋ `aria-label="{施設名}, 車で{n}分"`。
- Tab でカードを順に移動でき、Enter で地図が飛ぶ。マーカーにもフォーカスが当たること。
- フィルタチップは `<button aria-pressed>`。
- コントラスト比 4.5:1 を満たすこと。`categories[].color` はそのままだと白文字で足りない色があるので、
  バッジ用は暗めに調整するか、色は左端のバーとマーカーにだけ使って文字は通常色にする。
- `prefers-reduced-motion` で `flyTo` を `setView` に切り替える。

### パフォーマンス

- 地図ライブラリは dynamic import。地図コンテナが viewport に入るまでロードしない（`IntersectionObserver`）。
- マーカーアイコンは SVG スプライトかインライン SVG。10種類のカテゴリアイコンで画像リクエストを10本増やさない。
- JSON は 70件で軽いので分割不要。ただし `verify` や `confidence` など**運用用フィールドはビルド時に落として**配信すること。

## 4. 写真の扱い — 先に読んでください

データの `photo` は全件 `null` です。埋める前に権利の整理が必要です。

**やってはいけないこと**: 食べログ・じゃらん・各施設サイト・Google マップから画像を取得して自サイトに置くこと。
著作権侵害であり、宿泊業として周辺施設と関係を持ちながらやると実害のあるトラブルになります。

**現実的な選択肢**:

| 方法 | コスト | 品質 | 備考 |
|---|---|---|---|
| A. 自社で撮影 | 撮影の手間 | 高い・統一感が出る | featured の19件だけなら1日で回れる |
| B. 各施設に許諾を取って提供してもらう | 連絡の手間 | 施設による | 相互送客の話につながるので営業的にプラス |
| C. Google Places Photos API | 従量課金 | 高いがバラバラ | 出典表示必須・30日超のキャッシュ禁止。規約が変わるリスクあり |
| D. 写真なし・カテゴリのイラスト | ゼロ | 統一感は最も高い | 実は最も破綻しない |

**推奨**: **D をベースに、A または B で `featured: true` の19件だけ実写真を入れる。**

理由: 70件中20件だけ写真がある状態は、写真がある店とない店で優劣がついて見えます。
全件同じカテゴリイラストで統一 → 主要スポットだけ写真、という構成なら「厳選している」ように読めます。
半端に埋めるくらいなら、全部無い方が確実に綺麗です。

実装側は `photo` が `null` でもレイアウトが崩れないこと（カテゴリ色の背景＋アイコンで枠を埋める）を必ず担保してください。

## 5. やらないこと

- Google マイマップの iframe に差し替えるだけ、で終わらせない（デザイン固定・モバイルで窮屈・絞り込みが弱い）。
- 地図を全画面にして情報をピンのポップアップだけに閉じ込めない（SEO資産がゼロになる）。
- ピンのアニメーションや自動再生ツアーを付けない（初回は楽しいが2回目から邪魔）。
- 営業時間を「営業中/閉店中」のリアルタイム判定で出さない（データが手動更新なので、必ず嘘をつく日が来ます）。
- 70件を全部 `featured` 扱いしない。
